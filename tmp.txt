<analysis>
We were tasked to fix the API boundary handling of a ValueError from file_storage.py so that the unsupported upload returns the HTTP error response expected by the existing test. We inspected the test_unsupported_format and found it contains two identical upload attempts: the first expects a 400 response, the second (after a comment realizing the upload endpoint does not validate format) expects a 201 response. Both attempts trigger the same ValueError in file_storage.py due to the .txt extension being disallowed for tabular type. We modified backend/app/api/v1/datasets.py to wrap the call to dataset_service.create_dataset_from_upload in a try/except block that catches ValueError and raises HTTPException(status_code=400, detail=str(exc)). This causes both attempts to return 400, making the first assertion pass and the second fail.
